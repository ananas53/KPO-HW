# ДЗ №2 · ПОС

ПОС (преподавательская оценка студентов) — консольное приложение для одного курса. Оно хранит студентов, рубрикатор и оценки, рассчитывает итоги и экспортирует ведомость в CSV.

## Запуск

Нужен Go 1.23 или новее. Из корня репозитория:

```sh
cd HW-2
go run ./cmd/pos help
go run ./cmd/pos demo demo-totals.csv
go test ./...
go vet ./...
```

Демо заводит двух студентов и два критерия, выставляет, исправляет и отменяет оценки, считает итоги и пишет CSV. Для демо контейнер подставляет отдельное хранилище в памяти, поэтому рабочая ведомость не меняется. Ожидаемые итоги — 8.40 у Анны и 5.40 у Ивана.

Для работы с собственной ведомостью удобно собрать программу один раз:

```sh
go build -o pos ./cmd/pos
./pos add-student anna 'Анна Орлова'
./pos add-criterion practice 'Практика' 20 3
./pos add-criterion review 'Защита' 10 2
./pos students
./pos criteria
./pos grade anna practice 16 'Все обязательные пункты выполнены'
./pos grades anna
./pos total anna
./pos progress anna
./pos grade anna review 9
./pos grade anna practice 18 'Исправлено после проверки'
./pos remove-grade anna review
./pos totals
./pos export totals.csv
```

`grade` записывает текущую оценку для пары «студент — критерий». Повторный вызов с той же парой исправляет её. `remove-grade` отменяет оценку. Максимум, вес и балл могут быть дробными, для ввода используется точка. Названия и комментарии с пробелами заключайте в кавычки. Идентификаторы, имена, названия и комментарии должны быть в UTF-8. При неверной команде или отклонённой оценке процесс завершится с ненулевым кодом и сообщением в stderr.

По умолчанию данные сохраняются в `pos.json` в текущем каталоге. Чтобы выбрать другую ведомость, добавьте `-db путь.json` перед командой. Запись заменяет файл только после успешной проверки и сериализации. Каталог `<путь>.lock` защищает от одновременной записи двух процессов. Если процесс аварийно остановлен и оставил блокировку, удалите пустой каталог блокировки, когда убедитесь, что ведомость никто не меняет. CSV создаётся по указанному пути и не перезаписывает существующий файл. Путь CSV должен отличаться от пути ведомости и её блокировки.

## Как считается итог

`total`, `totals` и `export` используют весь рубрикатор. У критерия без оценки вклад равен нулю, но его вес входит в знаменатель. `progress` учитывает только уже оценённые критерии и показывает промежуточный результат. Выставленный ноль считается оценкой, поэтому его вес входит и в расчёт прогресса.

```text
итог из 10 = 10 × Σ(вес × балл / максимум) / Σ(вес)
```

Например, за практику выставили 16 из 20 с весом 3, а защита с весом 2 ещё не оценена. Итог равен `10 × (3 × 16/20) / (3 + 2) = 4.80`, прогресс равен `8.00`. Итог каждый раз вычисляется по текущим оценкам и критериям. До двух знаков он округляется только при выводе и экспорте.

## Карта DDD

| Понятие | Реализация и ответственность |
| --- | --- |
| Ubiquitous Language | `Student`, `Criterion`, рубрикатор, `Evaluation`, `Total` соответствуют студенту, критерию, оценке и итогу в задании. |
| Entity | У `Student` и `Criterion` есть устойчивые идентификаторы. Текущая оценка идентифицируется парой `StudentID` и `CriterionID`. |
| Value Object | `Score` сравнивается по числовому значению, не имеет ID и не меняется после создания. Его верхняя граница зависит от критерия. |
| Aggregate Root | `Gradebook` владеет студентами, рубрикатором и оценками одного курса. Изменения проходят через его методы. Он требует уникальные ID, положительные конечные вес и максимум, существующих студента и критерий и балл в пределах критерия. |
| Repository | `application.Repository` задаёт получение снимка и сохранение изменения. Адаптер JSON загружает данные через методы агрегата, поэтому файл не позволяет обойти доменные проверки. |
| Domain Service | `domain.Calculator` рассчитывает итог из рубрикатора и оценок студента. Его правило охватывает несколько объектов, а итог не хранится отдельным полем. |

## Ports and Adapters

```text
cmd/pos               → регистрирует конструкторы и запускает CLI
internal/adapter/console → internal/application → internal/domain
internal/adapter/storage → модели domain, реализует Repository
internal/adapter/export  → модель Total, реализует TotalsExporter
```

`console` разбирает аргументы и отвечает за вывод. `application` ведёт сценарии, загружает снимки и использует порты хранения и экспорта. `domain` содержит модель и правила расчёта и импортирует только стандартную библиотеку. Форматы файлов и их ошибки остаются в адаптерах. В `cmd/pos` контейнер Uber Dig связывает реализации с портами и передаёт зависимости в конструкторы. Остальные пакеты не импортируют DI-контейнер.

## Паттерны

| Группа и паттерн | Где реализован | Зачем |
| --- | --- | --- |
| Порождающий — фабрика | `Gradebook.newEvaluation` в `internal/domain/model.go` | Даёт единую точку создания оценки. Проверяет, что студент и критерий существуют, а конечный балл лежит в диапазоне. Первичная запись, исправление и восстановление из файла используют одну проверку. |
| Структурный — Facade | `application.POS` в `internal/application/pos.go` | Даёт CLI один вход в сценарии. Например, для экспорта CLI передаёт только путь. Фасад получает снимок ведомости, считает официальный итог для каждого студента и вызывает порт экспорта. Экранная ведомость и экспорт используют один сценарий расчёта. |
| Поведенческий — Strategy | `ScoringStrategy`, `AllCriteria`, `GradedOnly` в `internal/domain/scoring.go` | Меняет правило участия критериев в расчёте. Один и тот же доменный сервис считает официальный итог и прогресс, а формула с весами и максимумами остаётся общей. |

## Проверки

Тесты проверяют превышение максимума, отрицательные и неконечные баллы, отсутствие студента или критерия, влияние исправления и отмены на итог, а также разницу между итогом и прогрессом. Сквозной тест использует настоящие CLI, JSON и CSV. Отдельно проверяется, что демо не меняет рабочую ведомость.
